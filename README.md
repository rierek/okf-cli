# okf-tools

Navigation, search and maintenance for an **OKF Knowledge Catalogue** — a directory of markdown *bundles* whose concept pages carry typed frontmatter.

Two surfaces over one implementation:

- `cli/okf-cli.py` — the tool. Python standard library only, no install, no dependencies.
- `mcp/okf_mcp.py` — an MCP server exposing the mechanical verbs to agents. A thin subprocess wrapper; all correctness logic stays in the CLI.

Catalogue-aware fork inspired by Cole Medin's single-bundle `okf-cli.py`.

## Layout it expects

```
catalogue/
├── bundle-a/
│   ├── index.md          # marker-bounded listing, generated by `reindex`
│   └── concept.md        # frontmatter: type, title, description, tags, timestamp
├── bundle-b/
├── TYPES.md              # the valid type vocabulary
└── PROPERTIES.md
```

A bundle is an immediate subdirectory not starting with `.` or `_`. Run from the catalogue root, or pass `--root <path>`.

## Use

```bash
python3 cli/okf-cli.py prime                    # one-shot agent onboarding
python3 cli/okf-cli.py find "query" --limit 5   # hybrid search: BM25 + semantic
python3 cli/okf-cli.py find "query" bundle-a    # scoped to one bundle
python3 cli/okf-cli.py read bundle-a/concept
python3 cli/okf-cli.py check bundle-a           # conformance scan
```

`okf-cli.py --help` prints the command directory, flat and grouped by purpose; `okf-cli.py <command> --help` prints one command's options. Both are generated from the parser, so no file here carries a hand-maintained command list.

The verbs, by what they are for:

| purpose | commands |
|---|---|
| navigation | `index` · `info` · `list` · `recent` · `toc` · `read` |
| search | `find` · `tags` · `build-index` · `build-semantic-index` |
| integrity | `check` · `refs` · `wikilinks` · `log` |
| mutation | `rename` · `archive` · `reindex` · `merge-tags` · `remove-tags` · `normalize-tags` |
| repair | `fix-crosslinks` · `fix-xml-tags` · `rewrite-path` |
| output | `visualize` |

`rename` and `archive` are dry-run by default and need `--apply`. `rename` moves the concept, rewrites every inbound and outbound link, and reindexes — that is the only safe way to move a page.

## Search

`find` runs two arms and fuses them. The lexical arm is FTS5/BM25 over `<root>/.fts/fts.sqlite`, built by `build-index` — local, no network. The semantic arm needs `<root>/.tagvec/tag_vectors.sqlite`, filled by `build-semantic-index`, which calls voyage-3-large and therefore needs `VOYAGE_API_KEY` in the environment and a network connection. Without it the semantic arm is skipped and `find` says so.

Both indexes are built, not live. A catalogue that changed since the last build makes `find` print a staleness note rather than silently ranking against yesterday.

## MCP

```json
{
  "mcpServers": {
    "okf": { "command": "python3", "args": ["/path/to/okf-tools/mcp/okf_mcp.py"] }
  }
}
```

Fifteen tools, each mapping to one CLI verb, each taking `root` as its first argument.

## Development

```bash
just test          # unittest discovery over cli/test_*.py
just check         # conformance scan against a real catalogue
just prime
```

`just test` must be green before anything in `cli/` or `mcp/` is committed. Tests never write into a real catalogue — throwaway layouts go under their own tmpdir.

Work items live in `.beans/`; design notes and measurements under `docs/`. Both are internal to this working repo and are not part of the published mirror.
